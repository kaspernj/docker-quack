Buffered (non-streaming) requests now have a configurable timeout (`timeoutMs` connection option, default 120000ms; per-request override via `RequestOptions.timeoutMs`; `0` disables). Previously a host that accepted the connection but never responded would hang the request forever. The HTTP timer is provided by SnapReq and covers both response headers and buffered body reads. On timeout the request rejects with the new `DockerConnectionTimeoutError`, which is treated as a transient failure and retried when `retry` is enabled. `containers.stop()` derives its per-request timeout from the `t` grace period (plus the default as headroom) so a long graceful stop is never cut short by the default cap. Streaming requests (`requestStream`) are unaffected.
